# ADR 0003: Correct invalid BRD partition geometry

Status: **Accepted, 2026-10-26.** Implementation and paired verification pending.
Amends [ADR 0002](0002.md) only for the BRD max_part parameter behavior below.

## Decision

Adopt a deliberate correction for the declared 64-bit target:

| Parsed max_part | Effective value |
| --- | --- |
| Zero or negative | 1 |
| Greater than 256, including INT_MAX | 256 |
| 1 through 256 | Preserve baseline rounding to a supported power of two |

Parsing, other parameters and normal I/O retain the pinned contract. This
replaces Rust's provisional early EINVAL for negative values and intentionally
changes the already-tested high-positive INT_MIN/ENXIO behavior. It must be
reported as a selected fix, never as unchanged Linux 6.18.58 parity.

The June 2026 [upstream submission](https://lists.openwall.net/linux-kernel/2026/06/09/7)
proposes this ordering. It is a proposal; acceptance/merge has not been verified.
Preserve its authorship and obtain the original patch artifact before porting.
No upstream-maintainer approval is claimed.

## Why

The pinned C normalization can produce zero minors for negative inputs. Its
on-demand probe can then divide by zero. Positive inputs at least 2^30 also
produce invalid geometry. Existing tests cover the latter; negative guest
behavior has not yet been measured. Rust currently refuses negative geometry
earlier, so its parameter publication and major registration already differ.
The correction makes these invalid inputs yield working geometry.

## Required implementation and evidence

Retain pristine pinned C and its verification gate. Prepare a separately
identified baseline-plus-fix C oracle, then translate the correction into Rust.
Do not mix parser/parameter-storage redesign into this change. Test negative,
zero, rounding and high-positive boundaries with actual C/Rust BRD selection:
parameter values, registration, preallocated/on-demand disks, minor mapping and
I/O. Preserve historical results and failures; update compatibility records only
after these gates pass. Host kernels remain untouched. This alone does not
complete Phase 1a or its remaining parameter-ownership work.

## Alternatives and cost

Keeping early EINVAL is smaller but retains a deliberate compatibility exception.
Preserving prefault observations and refusing only the unsafe open needs more
registration/geometry complexity and still requires an explicit error contract.
This fix changes two invalid-input families and adds a maintained
selected-fix oracle/test inventory; it avoids reproducing broken device geometry.
