# Independent VMA modification source review

Result: no concrete source-level blocker found in the eleven-policy translation. Inputs and exact original-function hashes are in review.json. The reproducible read-only check.py removes only the new selection guards/includes and verifies the entire restored mm/vma.c against 99fd3dd96ac0b6131c34501dff9626e95b063037. All eleven original function regions also match pinned Linux 2926d88bb7fc4608fd942453d929c39e4e5ec006. Author formatting-only header updates were included in the final hash capture.

Reviewed each transaction:

- init_multi_vma_prep/init_vma_prep: canonical C storage is zeroed at its final address; middle/next retirement ordering, preferred adjustment target, anon fallback, mapping and uprobe suppression match C. Pointer-free Rust scalar bookkeeping replaces only the native pointer-to-remove-slot.
- vma_prepare: uprobe notification precedes mapping lock; early insert file linkage precedes anon lock/tree preparation; dcache lock and old interval removals retain native order. Insert publication calls the already selected Rust file-link implementation rather than a second C policy.
- vma_complete: adjusted interval then original interval publication, dcache release, remove/insert alternatives, count changes, anon post-update/unlock, mapping unlock and probes match. Retirement performs detach, probe/fput, anon merge, count decrement, policy drop, final-end warning and descriptor free. remove2 advances only after freeing the first descriptor; the freed pointer is not dereferenced afterward. Native merge admission excludes close-hook removals; retirement deliberately does not call vm_ops.close or the unrelated remove_vma transaction. Rust contains the equivalent small __remove_shared_vm_struct operation sequence; other C callers retain the original helper.
- __split_vma/split_vma: map-count check belongs only to the public split. may_split error returns unchanged; allocation/preallocation normalize to ENOMEM, policy and anon-clone errors propagate. Preallocation failure frees only descriptor, policy failure also frees iterator allocation, anon failure additionally drops policy. Native anon_vma_clone already unwinds its partial anon chains. File reference/open occur only after all fallible acquisition stages. Native write-start, prepare, huge split hooks, range/page-offset writes, complete, validate and iterator restoration match. Unsigned offsets and count arithmetic use explicit wrapping operations; no Rust bounds/panic arithmetic was added.
- vma_modify: saves native original VMA/start/end before merging, returns merged immediately without dereferencing potentially consumed originals, honors merge OOM, then splits leading/trailing ranges in original order. A successful first split is intentionally retained if the second split fails.
- flags/name/policy/flags_uffd: canonical VMG_VMA_STATE still initializes borrowed native context; successful merge propagates sticky flags only on VMA_MERGE_SUCCESS. Name/policy pointers remain borrowed. Userfaultfd aggregate passes by pointer to a C field-copy primitive, avoiding an empty/config-dependent aggregate ABI. Conditional give_up_on_oom assignment remains conditional.

ABI/build review: new C definitions have preceding header prototypes; exact bool/int/unsigned-long scalars and pointer-only canonical contexts agree with Rust declarations. vm_flags_t and pgoff_t use the native x86_64 unsigned-long representation. Nullable open and may_split callbacks use the actual native signatures, with no typed Rust descriptor reference retained across callbacks. Reused helpers are supplied by mandatory COPY_VMA/EXIT_MMAP ancestors; the new default-off Kconfig depends on COPY_VMA_RUST, inheriting its architecture/configuration restrictions, and Kbuild selects only vma_modify_rust.o. Private contexts, vma_prepare and VMG_VMA_STATE remain C-owned at final addresses. The original merge/shrink callers dispatch through selected prepare/complete wrappers too. Public split_vma retains its existing C prototype/call sites while Rust accepts its iterator as a pointer-only ABI.

No build, Kconfig resolution, actual binding regeneration, ELF ownership check, VM, failure injection or concurrency test was run. Retained binding presence reported by root is not a new compiled-candidate proof here. Actual emitted callback/bridge signatures, selection exclusivity and source-specific native tests remain required gates. Tests under rusix/tests/vma-modify are independently owned and are not included in this production review. Existing C merge eligibility, maple/rmap/slab/lock operations and all caller lifetime preconditions remain dependencies; this is not exclusive whole-VMA ownership.
